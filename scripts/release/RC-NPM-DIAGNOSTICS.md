For a nonzero numeric exit with string outputs (and no signal), only exact `error.code` in a bounded JSON object `{ "error": { "code": "..." } }` with optional `summary`/`detail`, or complete anchored stderr lines `npm error code CODE` / `npm ERR! code CODE`, contribute codes. The mapping inherited from #428 is: `ENEEDAUTH` → `NPM_AUTH_REQUIRED`; `E401` → `NPM_REGISTRY_UNAUTHORIZED`; `E404` → `NPM_REGISTRY_NOT_FOUND`; `EUSAGE` → `NPM_CLI_USAGE`; `E_STAGE_REQUIRED` → `NPM_STAGE_REQUIRED`; `EOTP` → `NPM_OTP`; `E403` → `NPM_FORBIDDEN`; `EACCES` / `EPERM` → `NPM_PERMISSION`. No independently verified distinct OIDC/trusted-publisher/environment/provenance code is mapped. Timeout is handled separately; never infer a category from prose.

Any conflicting, unknown or unsupported structured envelope is `NPM_UNKNOWN`, including JSON arrays, primitives and wrong-shaped objects. JSON-looking output beginning (after whitespace) with `{`, `[`, `"`, a digit/`-`, or whole-word `true`, `false`, `null` is rejected if malformed. Ordinary stdout notices are not structured evidence. #432's conservative code classifier (including escaped JSON rejection) is unchanged. The separate human diagnostic boundary does **not** require a known category or npm code: an unambiguous sanitized anchored code can appear as diagnostic text without becoming a trusted category. Stdout is validated for capture shape/bounds but never selected/serialized, including malformed/conflicting JSON; stderr code text is not a claim that competing stdout is valid.

## Public output contract

`SafePublishFailure` contains only reviewed package/version, capped timings/channel byte counts and sanitized diagnostics. No original child Error.message, stack, cause, command or environment is attached. `runProtectedRc` propagates this class's safe message after read-only reconciliation and stops without next package/tag; arbitrary exceptions still receive the existing fixed fallback.

Diagnostics contain fixed exit (0..255 or unavailable), signal (known allowlist or unavailable), process/timeout-or-kill/spawn reason, sanitized npm code (or unavailable), redaction/truncation/omission/suppression metadata, a <=300 UTF-8-byte message and last six eligible <=180-byte human lines. The complete publish failure message is <=2KiB and <=10 physical lines with reviewed metadata; byte-aware truncation never cuts a Unicode code point. Every child-derived line has a fixed `[npm diagnostic]` prefix. `::` is replaced with `[COMMAND]`. Omission is always explicit: stdout, debug-log pointers, stack frames and header dumps are not eligible. Selection defaults to anchored `npm error`/`npm ERR!`; observed pre-config `Exit prior to config file resolving` and `double-loading config` lines are eligible without a code. No full debug-log artifact or raw stderr is stored.

Complete bounded capture is checked **before** known-value replacement, selection or truncation. Recognizable auth/bearer/header/cookie hints or credential assignments (including quoted JSON keys, mixed case, TAB/Unicode whitespace and decoded percent forms) in **either channel** suppress **all human detail from both channels** with fixed `suppression=AUTH_MATERIAL_DETECTED`. No partial line redaction is attempted: even a complete-looking assignment can introduce unmarked credential continuations. Surrounding safe lines and npm code text are also withheld; reviewed metadata/category/byte counts remain. Synthetic independent auditor repros cover message, stack, String, JSON serialization, Node util.inspect and actual Node Console formatting, fake-exec cleanup and runProtectedRc stop/reconciliation propagation.

Known values are collected in memory from parent credential-bearing token/auth/password/secret/key/credential keys before spawn (the minimal publish env's OIDC fields are included); nothing is added to the child env. Without auth syntax, arbitrary known values, overlap, multiline and exact JSON-escaped or URI-percent forms are replaced. Percent sequences are decoded up to three rounds with known-value replacement each round. Remaining backslash/percent encodings, invalid UTF-8/surrogates, >=100,000-byte/incomplete captures, control/ANSI/OSC/CR/bidi/Unicode separator input and sanitizer exceptions withhold the capture with a **fixed suppression reason**, not a silent unknown category. Known one/two-character credential values suppress all human detail conservatively. Named npm/GitHub tokens and JWT patterns are removed; complete scheme URLs (including userinfo, all query/fragment data and OIDC endpoints) are removed. Unknown captures get an explicit no-eligible-human message rather than raw fallback. Ordinary npm EUSAGE and pre-config no-code double-loading strings remain useful when no credential syntax is present. This intentionally prefers false-positive suppression over irreversible partial credential disclosure.

**Residual risk:** Public repository logs are irreversible disclosure. Redaction is not universal arbitrary-secret isolation, does not identify arbitrary unknown app secrets or every transformation, and is not a hostile-JS sandbox. Safety depends on the unchanged minimal child environment, in-memory known-value redaction and npm not printing unrecognized secrets by default. Unsupported recognized transformations suppress detail; this is not proof every possible transformation is recognized. No reliance solely on GH masking. Independent security-focused audit and exact-head CI are required before any separately authorized future run.
